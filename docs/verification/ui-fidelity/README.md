# DRIVELOG Mobile UI fidelity verification

## Crash reproduction and fix

On the Pixel emulator, tapping **정보** in the editor reproduced a main-thread crash:

```text
java.lang.NoSuchMethodError: No static method FlowRow(...)
  at com.drivelog.mobile.feature.editor.EditorScreenKt.InfoControls(EditorScreen.kt:117)
  at com.drivelog.mobile.feature.editor.EditorScreenKt.EditorScreen(EditorScreen.kt:63)
```

The compiled `FlowRow` call did not match the Compose Foundation implementation packaged in the installed APK. `InfoControls` now uses stable `Column` and `Row` controls with explicit monochrome switch colors. After installing the changed APK, the tab opened on all three demo records without a new `AndroidRuntime` exception.

## Emulator checks

- Pixel emulator, Android display 1080×2424 at density 420 (about 412dp wide); temporary 945×2121 override (about 360dp wide) was restored after screenshots.
- Home: vehicle status, recent drive hero, two feature cards, and fixed bottom navigation displayed. No photo was assigned to the demo records for the final home screenshot.
- Editor: filter, layout, info, crop, and save tabs opened. Route and distance switches remained off after layout → crop → info navigation.
- Crop with a temporary media fixture: zoom 2.50×, X +0.34, Y −0.50; reset restored 1.00× and both axes to center. A drag on the card changed X/Y to +0.39/+0.04.
- Final preview and exported PNG used the same `CardDraft`/CardJson settings. The exported bitmap was 1200×1600 and was saved by Android's CreateDocument flow.
- The temporary media fixture was a screenshot used only for verification. Its local app copy and emulator media copies were removed after the check. It was never added to `DemoJourneys`.
- `:app:assembleDebug :app:testDebugUnitTest` passed.
